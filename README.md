# Rodillian Runners — Static Site

Hugo-built static site for Rodillian Runners running club, replacing the WordPress install on Ionos.

## What this is

A static site generated by [Hugo](https://gohugo.io/) (extended, v0.145+). No PHP, no database, no WordPress. The output (`public/`) is plain HTML, CSS, and JS that can be served from any static host.

## How content is organised

```
content/         Markdown for every page (home, contact, club-records, etc.)
data/records/    Club records JSON (Female, Male, 2020 League, 2020 Improvers)
themes/rodillian/ Custom theme: layouts, CSS, JS, assets, partials
  layouts/       baseof.html + per-page templates (single, list, records, calendar)
  static/        css/, js/, images/, documents/ — served at site root
  static/calendar.ics (auto-generated by build hook, do not edit)
scripts/         Pre-build hooks (fetch-calendar.sh pulls live ICS feed)
```

## How the calendar works

`scripts/fetch-calendar.sh` runs before each Hugo build. It pulls the live ICS feed from Google Calendar and writes it to `themes/rodillian/static/calendar.ics`. The browser-side `calendar.js` fetches that file (same origin, no CORS) and renders month-by-month with prev/next nav, expanding recurring events (`RRULE`) inline.

Source calendar (Google): `6jcd9u7log0u6clot6kduuntms@group.calendar.google.com`. Public ICS URL is in `hugo.toml` under `hooks.pre.commands`.

To refresh the calendar between deploys, edit events in Google Calendar and trigger a Railway redeploy.

## How the contact form works

## Local development

```bash
# Hugo extended >= 0.145 must be installed and on PATH
hugo server --port 1313 --bind 127.0.0.1
```

Site available at http://127.0.0.1:1313.

The server watches `content/`, `data/`, `themes/`, and `hugo.toml` for changes and rebuilds live. Changes to `themes/rodillian/static/calendar.ics` require a manual rebuild (or rerun `bash scripts/fetch-calendar.sh`) since the hook only runs on `hugo build` not `hugo server`.

## Build

```bash
hugo --minify
```

Output is in `public/`. Static — deploy anywhere.

## Deployment

Pushed to GitHub, deployed via Railway. Each PR gets a preview deployment. Production deploys on merge to `main`.

DNS cutover (when ready): point `rodillianrunners.co.uk` A and CNAME records at the Railway-provided hostname. Cancel Ionos hosting after 30 days stable.

## Editing content

Each page is a Markdown file in `content/`. The site uses Hugo's "page bundles" model — `content/club-activities/championship.md` becomes `https://rodillianrunners.co.uk/club-activities/championship/`.

To update club records:
1. Edit `data/records/female.json` or `data/records/male.json`
2. Each row is an array; rows are grouped in 3s per distance
3. Open a PR, preview on Railway, merge when happy

To update the calendar:
1. Edit the Google Calendar directly at calendar.google.com
2. Push a commit (or trigger Railway redeploy) — the build hook fetches the latest ICS
3. New events appear after the next deploy
